# Source comparison: webmcp_flutter and intentcall_webmcp

## Scope and pinned evidence

This closes the `intentcall_webmcp` prerequisite for the release plan. It compares the current local `lib/**` and focused tests with the complete implementation shipped in the published `intentcall_webmcp` archive. It is not a feature-parity requirement. The accepted first release remains the existing detection-first registry at `webmcp_flutter` 0.1.0; a browser bridge is deferred.

## Conclusions for the release plan

The published package demonstrates a useful adapter pattern: attach-time publication, event-driven hot synchronization, normalized success/failure maps, and detach cleanup. It does not itself provide a browser binding or live-browser proof. Local `webmcp_flutter` instead provides a deterministic registry, explicit Flutter scopes/actions, and standards-aligned `document.modelContext` detection, while deliberately omitting browser publication.

The comparison finds no accidental omission that invalidates the accepted detection-first 0.1.0 scope. The local partial source-registration behavior, mounted descriptor identity, reset cleanup gap, and callback-failure ambiguity must be disclosed as limits; they do not require feature parity or a browser bridge for this release plan. If browser publication is later selected, cleanup, failure atomicity, result normalization, schema ownership, and live host interoperability require a new research/plan/validation cycle.
