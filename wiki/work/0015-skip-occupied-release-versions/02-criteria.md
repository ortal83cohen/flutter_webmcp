# Acceptance criteria: Skip occupied package versions instead of failing the release bump

## Frozen

- Frozen at: 2026-09-16
- Frozen by: orchestrator

## Criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-001 | When OCCUPIED_VERSIONS is unset or empty, tools/bump_patch_version.sh running against a fixture whose pubspec version is 0.1.1 shall exit zero, print the single standard-output line 0.1.2, write that version into pubspec.yaml, and insert a changelog heading for 0.1.2. | Run the helper against a temporary copy of the valid-patch fixture with the variable unset, and again with it set to the empty string; compare standard output, the written version line, and the new heading. | Run the same fixture with OCCUPIED_VERSIONS set to 0.1.2: the helper shall not print 0.1.2 as the chosen version. |
| AC-002 | When the helper runs against a fixture whose pubspec version is 0.1.1 and OCCUPIED_VERSIONS contains 0.1.2 and not 0.1.3, it shall exit zero, print 0.1.3, write version 0.1.3, insert a changelog heading for 0.1.3, and insert no new heading for 0.1.2. | Copy a plus-one fixture, export that occupied list, run the helper, and assert stdout, the pubspec line, presence of the 0.1.3 heading, and absence of a newly inserted 0.1.2 heading. | Run the same tree with OCCUPIED_VERSIONS unset: the helper shall choose 0.1.2, proving the skip depends on the occupied list rather than on the fixture files alone. |
| AC-003 | When the helper runs against a fixture whose pubspec version is 0.1.1 and OCCUPIED_VERSIONS contains 0.1.2 and 0.1.3 and not 0.1.4, it shall print 0.1.4, write that version, insert a heading only for 0.1.4, and insert no new heading for 0.1.2 or 0.1.3. | Run the consecutive-occupied fixture and assert stdout 0.1.4, the pubspec line, exactly one new heading, and that heading's version is 0.1.4. | Occupy only 0.1.2: the helper shall choose 0.1.3, not 0.1.4, so extra skips cannot be incidental. |
| AC-004 | When the helper runs against a fixture whose pubspec version is 0.1.1 and OCCUPIED_VERSIONS contains 0.1.3 and not 0.1.2, it shall print 0.1.2 and write 0.1.2, leaving plus-one unchanged. | Run the later-not-next fixture and assert stdout and the written version are 0.1.2. | Occupy 0.1.2 as well: the helper shall then choose 0.1.4 or 0.1.3 according to whether 0.1.3 is in the list, not 0.1.2. |
| AC-005 | When the first candidate and the next fifty patch numbers are all in OCCUPIED_VERSIONS, the helper shall exit non-zero, leave both files byte-identical to the pre-run copies, and write an English message to standard error that contains the decimal number 50. | Build an occupied list of fifty-one consecutive patches starting at current plus one, run the helper, compare checksums, and grep standard error for 50. | Build a list of fifty consecutive occupied patches starting at current plus one, leaving the fifty-first candidate free: the helper shall exit zero and write that free version, proving the cap has not already fired one step early. |
| AC-006 | When OCCUPIED_VERSIONS contains a token that is not exactly three numeric components, the helper shall exit non-zero and leave both files byte-identical to the pre-run copies. | Run a fixture with a two-component token, a prerelease token, and a non-numeric token, each in a separate run; assert non-zero exit and matching checksums. | Run the same fixture with only well-formed three-component tokens that do not include the plus-one version: the helper shall exit zero and write plus-one. |
| AC-007 | When the chosen free version already has a changelog heading, the helper shall exit non-zero and leave both files byte-identical, including when that chosen version is not current plus one because an earlier patch was occupied. | Fixture pubspec 0.1.1, occupied 0.1.2, changelog already heading 0.1.3: assert non-zero exit and byte-identical files. | Same pubspec and occupied list with no 0.1.3 heading: the helper shall exit zero and write 0.1.3, so the reject is the heading, not the skip. |
| AC-008 | When tools/test_bump_patch_version.sh runs, every case that existed before this work item shall still pass, including valid-patch, valid-minor-untouched, valid-leading-blank, the current reject-changelog-ahead disagreement, and the real-repository plus-one copy. | Run the test script and assert those named cases print PASS; read the script and assert it unsets OCCUPIED_VERSIONS for those cases. | Export OCCUPIED_VERSIONS in the parent environment to the plus-one version and run only the existing valid-patch case: it shall still plus-one, proving the unset is effective. |
| AC-009 | When tools/occupied_pubdev_versions.py reads fixture JSON whose versions array lists several three-component versions, it shall exit zero and print those version strings as one space-separated line in document order, both from a file path argument and from standard input. A versions[].version that is not exactly three numeric components shall be omitted from that line and shall not by itself make the parser exit non-zero. | Run the parser on a fixture file and again with the same bytes on standard input; compare standard output to the fixture's expected list. Run a mixed fixture whose versions array also contains a prerelease string and assert that string is absent from standard output and that the exit status is zero. | Feed the parser JSON whose versions array is missing: it shall exit non-zero and print no version list on standard output. |
| AC-010 | When the parser reads fixture JSON in which a versions entry has retracted set to true and a three-component version string, that version string shall appear in the printed occupied list. | Run the retracted fixture and assert the retracted version token is present in standard output. | Run a copy of the fixture with that versions entry removed: the printed list shall not contain that version string. |
| AC-011 | When the parser is given invalid JSON, or JSON whose versions value is not an array, it shall exit non-zero and leave standard output empty. | Run the invalid-JSON fixture and the versions-is-object fixture; assert non-zero exit and empty standard output. | Run a fixture whose versions value is an empty array: the parser shall exit zero and print an empty line, distinguishing missing from empty. |
| AC-012 | When the parser reads fixture JSON whose latest.version is one three-component string and whose versions array also lists older three-component strings, the printed list shall include those older strings, not only latest.version. | Run a fixture modelled on a package list where latest is 0.1.6 and versions also includes 0.1.0 and 0.1.1; assert all three appear. | Run a fixture whose versions array contains only latest.version: the printed list shall be that single token, so extra tokens cannot be hard-coded. |
| AC-013 | When bash tools/check.sh runs to completion, its output shall include a passed-stage line for the occupied-pubdev-versions test, and that stage shall follow the existing version-bump test stage. | Run the full check suite and read the new passed-stage line; read the script and confirm the new stage uses the existing failure-reporting helper and numbering sequence. | Make the parser test script exit non-zero and re-run the suite: the suite shall stop at that stage with a non-zero exit. |
| AC-014 | When .github/workflows/release.yml is parsed, a step after the check-suite step and before the bump-helper step shall GET https://pub.dev/api/packages/webmcp_flutter, parse the body with tools/occupied_pubdev_versions.py, and export OCCUPIED_VERSIONS from that parser's standard output; that occupancy step shall not list git tags into the occupied variable. | Parse the workflow, compare step indices, and read the occupancy step body for the URL, the parser invocation, the environment export, and the absence of git tag listing commands used to build the list. | Assert the bump step index is greater than the occupancy step, and that a copy of the occupancy step which concatenates git ls-remote tag names into OCCUPIED_VERSIONS fails this reading. |
| AC-015 | When the occupancy step sees a non-200 HTTP status, a zero-length body, or a parser failure, it shall exit non-zero, and the bump helper shall not run in that job. | Read the occupancy step and assert it tests status against 200, tests body length, and propagates a non-zero parser exit; assert the bump step has no always-run or continue-on-error setting that would invoke the helper after that failure. | Assert a scratch variant that treats status 404 as success, or that calls the bump helper after a failed GET, disagrees with the committed step body. |
| AC-016 | When the release workflow is parsed, the step between the bump-helper step and the commit step shall still fail the job when a tag named v plus the bump step's version output already exists locally or on the remote. | Read that step, assert it fetches tags and exits non-zero on an existing matching tag, and assert its index still lies between bump and commit. | Simulate the step body in a scratch repository that already holds a tag for the bump output and assert a non-zero exit; simulate the same body with no matching tag and assert exit zero. |
| AC-017 | When the change is complete, .github/workflows/checks.yml shall be byte-identical to its state on the work-item base commit. | Run a git diff limited to that path against the base and assert empty output. | Append a blank line to a scratch copy and diff against the copy: the diff shall be non-empty. |
| AC-018 | When the change is complete, the top-level pubspec.yaml version line shall equal the version on the work-item base commit, CHANGELOG.md shall gain no new version heading, and the repository shall gain no new annotated or lightweight tag named v followed by three numeric components, because this implementation does not itself perform a release. | Diff pubspec.yaml and CHANGELOG.md against the base; list tags matching that shape and compare to the base tag list. | In a scratch clone, bump the pubspec version by one, add a heading, and create such a tag: each of those three checks shall report a difference. |
| AC-019 | When a changelog already contains a heading for an occupied intermediate version, and the chosen free version has no heading, the helper shall exit zero and write the free version rather than reject. | Fixture pubspec 0.1.1, occupied 0.1.2, existing heading 0.1.2, no heading 0.1.3: assert exit zero, stdout 0.1.3, and a new 0.1.3 heading. | Remove 0.1.2 from the occupied list on the same files: the helper shall reject because 0.1.2 is then the chosen version and already has a heading. |
| AC-020 | When .github/workflows/publish.yml is compared to the work-item base, it shall be byte-identical, and the release workflow shall still contain the job-level loop guard on the chore(release): v prefix, still push the commit before the tag, still create an annotated tag, and still contain no force-push, no ref deletion, and no GitHub skip instruction. | Path-scoped diff of publish.yml; parse release.yml for the guard, push order, annotated tag, and grep for force-push of a tag or branch, for ref deletion, and for skip-instruction strings. The existing git fetch of tags with a force flag on fetch is not a force-push and shall not fail this check. | Assert a scratch copy of release.yml that force-pushes the tag, or that inserts a skip instruction in the commit message, fails those greps. |

## Non-functional criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-021 | When tools/bump_patch_version.sh is read and when tools/test_bump_patch_version.sh runs, neither shall open a network connection or invoke git. | Read both scripts and confirm they reference no host name, no URL, and no git command; run the test script with no network reachable and assert exit status zero. | Add a temporary case that resolves a host name or calls git and run the suite offline: that case shall fail. |
| AC-022 | When tools/occupied_pubdev_versions.py and tools/test_occupied_pubdev_versions.sh run, neither shall open a network connection or invoke git. | Read both files and confirm they reference no host name, no URL, and no git command; run the test script with no network reachable and assert exit status zero. | Add a temporary case that fetches a URL and run the suite offline: that case shall fail. |
| AC-023 | When the occupancy step in the release workflow is read, it shall send an Accept header whose value is application/vnd.pub.v2+json, shall not send an Authorization header, shall not append a query string to the package-list URL, and shall reference no pub.dev password, token, or credentials file. | Read the occupancy step body and grep it for the Accept value application/vnd.pub.v2+json, and grep the release workflow for Authorization, query-string markers on that URL, and pub.dev credential vocabulary. | Plant an Authorization header or a query string on a scratch copy of the step: those greps shall match. A scratch copy whose Accept value is application/json and not application/vnd.pub.v2+json shall fail the Accept grep. |
| AC-024 | When the helper rejects because of a malformed occupied token, a cap that was exceeded, or a chosen-version changelog heading, neither pubspec.yaml nor CHANGELOG.md in the target root shall differ by a single byte from its pre-run content. | Checksum both files before and after each of those three reject runs and compare. | Re-run the comparison against a copy modified by one byte after checksumming: the comparison shall report a difference. |

## Explicitly not required

- Request-based changelog text, minor bumps, or major bumps.
- Publishing 0.1.2, 0.1.3, or any other real package version during this work item.
- Deleting tags, force-pushing, or recovering a tag that exists for a version that is not on pub.dev. That recovery is work item 0013.
- Recovering a release commit that landed without its tag. That recovery is work item 0013.
- Editing .github/workflows/publish.yml or .github/workflows/checks.yml.
- Sleeps, cache-busting query strings, or defeating the hosted-list Cache-Control max-age of one hundred and twenty seconds.
- Unpublish handling other than: if a version is still present in versions[] it is occupied.
- A stored pub.dev credential.
- Putting git tags into OCCUPIED_VERSIONS.
- An end-to-end main-branch release during verify. Verification is offline helper tests plus static reading of the workflow files.
