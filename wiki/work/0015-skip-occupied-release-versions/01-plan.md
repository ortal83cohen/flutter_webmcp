# Plan: Skip occupied package versions instead of failing the release bump

## Goal

A push to main that would have produced a patch version already hosted on pub.dev for webmcp_flutter shall, in that same release run, write, commit, and tag the next free patch in the same major and minor line. An observer of a successful run sees one new pubspec version, one new changelog section for that free version only, and one annotated tag for it. A version that is hosted, including a retracted hosted version, is never reused. An unpublished git tag for a version that is not hosted remains a hard failure of the existing tag-collision step, not a reason to skip to a later patch.

## Approach

The skip lives in the existing POSIX bump helper. That helper already owns version arithmetic and the changelog rewrite, and it is already tested offline. It gains one new input: an environment variable named OCCUPIED_VERSIONS, a single space-separated list of three-component numeric versions. Unset or empty restores today's plus-one behaviour, so every existing fixture and the real-repository plus-one case keep passing. When the variable is set, the helper starts at current patch plus one and, while the candidate is in the occupied set, adds one to the patch, leaving major and minor copied. It stops at the first candidate that is not in the set, or it fails if fifty increments from the first candidate still leave the candidate occupied. It writes both files once, for the chosen free version only. Intermediate occupied versions receive no changelog section. The changelog heading check still applies only to the version about to be written; if that heading already exists, the helper rejects as it does today and leaves both files untouched.

The occupied set is assembled by the release workflow, not by the helper, because the helper must remain free of git and of network. After checkout, after the existing Python 3.12 setup, and after the package check suite, a new step runs before the bump helper. It performs an unauthenticated GET of the official hosted package list for webmcp_flutter, sending the pub.dev v2 JSON Accept header and no Authorization header and no query string. Python 3.12 is already installed in this job; the GET uses that interpreter's standard-library HTTP client so the plan does not depend on whether the runner image still ships curl, which research left unresolved. A non-200 status or a zero-length body fails the step with an English message and never invokes the bump helper. The response body is written to a runner file and parsed by a new small Python helper that reads JSON from a file path or from standard input and prints the space-separated occupied list. That parser is tested offline against fixture JSON. The printed list is exported as OCCUPIED_VERSIONS for the bump step. Git tags are not added to that list. The existing fetch-tags and tag-collision step stays where it is today: after the helper writes the chosen version, and still a hard fail if a local or remote tag already names that chosen version.

The publish workflow is not edited. The loop guard, commit-then-tag order, absence of GitHub skip instructions, and the ban on tag delete and force-push stay as they are. Same-version recovery of an unpublished tag, and recovery of a release commit without its tag, remain work item 0013.

## Why this approach

Research records the current behaviour as a hard fail, not a skip: the helper rejects a changelog heading for the computed version, and the release job then rejects a matching git tag. Pub.dev is not consulted. Skip-strategy chose a helper that accepts an occupied set and writes the first free patch in one invocation, with the workflow supplying the set. That option is chosen here because a single write produces one changelog section for the free version, the helper stays fixture-testable without a network, and an unpublished existing tag can be omitted from the skip set so the collision step still fails, which is publish-retry rather than skip-next.

A workflow loop of the existing plus-one helper was rejected: reverting the two files repeats the same next patch, so the job would have to mutate the starting version between attempts, which moves arithmetic into untested YAML and still has to discard changelog sections for skipped versions. Changing only the tag-collision step from fail to try-next was rejected: the helper has already written the occupied version, ignore-and-continue then fails at tag create or tag push, and treating every existing tag as occupied would skip a tagged unpublished version, which 0013 classifies as publish-retry. Keeping the human-bump failure was rejected because it does not meet the outcome.

Occupancy-signals chose the official hosted list GET as the pub.dev oracle and rejected the deprecated per-version URL, the undocumented packages JSON listing, and learning occupancy from a publish dry-run or a real publish failure, which run after the tag exists. Those rejections stand. Occupancy-signals treated tag existence as occupancy of the candidate; skip-strategy and this plan do not put tags in the skip set. The parent locked that disagreement in favour of skip-strategy: hosted pub.dev versions only, including retracted ones; the existing tag-collision step remains the publish-retry gate.

## Interfaces and shared decisions

Occupied-set membership. The skip set is hosted pub.dev versions of the package webmcp_flutter only. Every string in versions[].version of the official package-list response is occupied if it is exactly three numeric components. Retracted hosted versions are occupied; the retracted field is status, never a free slot. Git tags are not in the skip set. latest.version is not the occupancy set. A tag that exists for a version that is not on pub.dev is publish-retry: the helper may still compute that version as current plus one, and the existing tag-collision step then fails. This work item does not recover that tag.

Helper occupancy input. The variable is OCCUPIED_VERSIONS. It is a single string. The helper splits it on any run of whitespace and discards empty tokens. Unset, empty, or whitespace-only means today's plus-one path; every existing fixture must still pass. Every remaining token must be exactly three dot-separated numeric components; any other token is a malformed occupied token. On a malformed token the helper exits non-zero, writes neither pubspec.yaml nor CHANGELOG.md, and prints an English message to standard error that names the malformed token. Duplicate tokens are membership only and are harmless. Matching a candidate is exact string equality.

Skip arithmetic and cap. The starting candidate is the current pubspec patch plus one, with major and minor copied unchanged. While that candidate is in the occupied set, add one to the patch. Do not perform more than fifty such additions from the first candidate. The helper may therefore consider at most fifty-one version numbers: the first candidate and fifty successors. If after fifty additions the candidate is still in the occupied set, the cap is exceeded: exit non-zero, write neither file, and print an English message to standard error that names the cap as the decimal number fifty. The cap is a helper constant, not a workflow-supplied value. Major and minor never change. The helper still prints exactly one standard-output line on success: the chosen version, with no v prefix.

Changelog heading check. After the free version is chosen and before either file is written, apply today's heading check only to that chosen version. Intermediate occupied versions do not receive a section and are not required to lack a heading. A heading that already names an occupied intermediate version does not by itself reject the run. If the chosen free version already has a heading, reject as today: non-zero exit, English message naming that version, both files untouched.

JSON parser. The file is tools/occupied_pubdev_versions.py. It uses only the Python 3 standard library. With one positional argument it reads that file path; with no positional argument it reads standard input. It does not open a network connection and does not invoke git. It parses the body as JSON. It requires a top-level versions key whose value is an array. It prints one line of standard output: the versions[].version strings that are exactly three numeric components, separated by a single space, in document order; an empty versions array prints an empty line and exits zero. A versions[].version that is not three numeric components is omitted from the printed list and does not fail the parser, because such a hosted string cannot equal a patch candidate this bump helper produces, and emitting it would make the bump helper fail closed. The retracted field is ignored for membership: a retracted three-component version is printed. The latest object is ignored except insofar as its version also appears in versions[]. On invalid JSON, a missing versions key, or a versions value that is not an array, the parser exits non-zero, prints an English message to standard error, and prints nothing on standard output. Parser tests live in tools/test_occupied_pubdev_versions.sh with fixture files under tools/fixtures/occupied-pubdev-versions, and that test script is a new stage of tools/check.sh after the existing bump-helper stage.

Occupancy fetch in the release job. Placement: after the existing checkout, after the existing Python 3.12 setup, after the existing package check suite, and immediately before the bump step. Tag fetch stays in the existing collision step after the bump, as today. The new step GETs https://pub.dev/api/packages/webmcp_flutter with the Accept header whose value is the media type application/vnd.pub.v2+json. It sends no Authorization header, stores no pub.dev credential, and appends no query string and no cache-busting parameter. It uses Python 3.12's standard-library HTTP client already available in this job, with a finite timeout of at most sixty seconds so a hung GET fails the job rather than bumping blindly. It writes the response body to a runner-local file. If the final HTTP status is not 200, or the body has length zero, the step prints an English error to standard error naming the failure and exits non-zero; the bump helper is not invoked. It then runs the JSON parser on that file. A non-zero parser exit fails the step. The parser's standard-output line is written to GitHub's environment file as OCCUPIED_VERSIONS so the following bump step inherits it. That list is the only occupied-set input the bump helper receives. The occupancy step does not consult git tags when building the list.

Tag-collision step. Unchanged in role: after the helper, before the commit, fetch tags and fail if a local or remote tag named v plus the bump step's version output already exists. Because the bump output is now the chosen free version, the collision check applies to that version. A tag for a skipped occupied version is irrelevant to this step. No tag is deleted. No push is forced.

What is not edited. .github/workflows/publish.yml is not edited. .github/workflows/checks.yml is not edited. The job-level loop guard that skips a head commit message beginning with the release prefix chore(release): v remains. Commit is still pushed before the annotated tag. No GitHub skip instruction is added to any commit message this job writes.

Implementation restraint. Implementation does not bump the real package version in the repository pubspec, does not add a changelog section for a new version, and does not create a release tag. The first skip or plus-one bump belongs to a later main-branch run of the automation.

Residual cache. The hosted list may be cached for up to one hundred and twenty seconds. That is accepted. A version published inside that window may be absent from a cached read; the next non-release push then skips a version that appeared after the cached read. This plan adds no sleep and no cache-busting query string.

Unresolved items this plan does not reopen. Research questions about publish dry-run messages, lightweight versus annotated tags in every clone state, whether a heading-without-tag split has been observed, commit-without-tag recovery, a rare unpublish, and curl on ubuntu-latest are not answered here. Dry-run behaviour is out of scope. Commit-without-tag and unpublished-tag recovery are 0013. Curl is not required because the GET uses the Python already installed in the job. Unpublish: if the version is still in versions[] it is occupied; this work item adds no other unpublish handling. The increment cap and the OCCUPIED_VERSIONS input, which research left unresolved, are the decisions in this section.

## Risks

| Risk | Likelihood | Impact | Mitigation | Trigger that means it happened |
|---|---|---|---|---|
| The hosted package-list GET returns non-200, an empty body, or JSON without a versions array | Medium | The release job fails and no version is written, which is fail-closed rather than a colliding publish | Occupancy step fails the job and the bump helper is not invoked | A bump-and-tag run fails at the occupancy step with an English GET or parse error and pubspec.yaml on main is unchanged |
| CDN cache of the package list is up to one hundred and twenty seconds stale | Medium | The next non-release push may skip a version that was published after the cached read, consuming an extra patch number | Accepted residual risk; no sleep and no cache-busting query string | A patch number on pub.dev is missing while a later patch from this automation exists, and the missing number appeared on the list shortly after the run |
| Fifty consecutive hosted patches from the first candidate, or a malformed occupied token, fail the helper | Low | The release job fails with files on the runner discarded | Cap and malformed-token failures leave both files unwritten; the message names the cap or the token | A run fails at the bump step with that English error and no release commit lands |
| An unpublished tag for current plus one still fails the job | High, by design, while tags such as v0.1.2 exist without a hosted version | Main-branch release of that number still fails; a later free hosted number is not chosen | Skip set excludes tags; collision step remains a hard fail; recovery is 0013 | A run writes a candidate that is not on pub.dev, then fails at the tag-collision step |
| Implementation bumps the real package or publishes during the work item | Low | A production version is consumed without a product change | Restraint criteria and the verify step forbid editing the real pubspec version, adding a changelog heading, or creating a tag | git diff of pubspec.yaml against the base shows a version change, or a new v-prefixed tag exists |
| Putting git tags into OCCUPIED_VERSIONS would skip a tagged unpublished version | Medium if the occupancy step is written carelessly | 0013 publish-retry becomes skip-next | Occupancy step builds the list only from the parser output of the public package list | The occupancy step body lists git tag refs into OCCUPIED_VERSIONS |

## Rollback

Revert the edits to tools/bump_patch_version.sh, tools/test_bump_patch_version.sh, .github/workflows/release.yml, and tools/check.sh, and delete the added parser, its test script, its fixture directory, and any new bump-helper fixtures. That restores plus-one bumping and the previous hard-fail occupancy behaviour. No data migration is required.

Any version this automation later publishes remains permanent on pub.dev. Rolling back the skip logic does not unpublish. Implementation of this work item must not itself publish, so rollback during implement-and-verify is a git revert of the automation only.

## Out of scope

Request-based changelogs, minor bumps, and major bumps. Publishing 0.1.2 or 0.1.3, or any real package version, during this work item. Deleting tags. Force-push. GitHub skip instructions. Editing publish.yml or checks.yml. Same-version tag recovery and commit-without-tag recovery (work item 0013). Unpublish handling beyond membership in versions[]. Sleeps or cache-busting query strings. A stored pub.dev credential. Putting git tags into the skip set. Changing the loop guard or commit-then-tag order.

## Verification approach

The bump helper is checked by running tools/test_bump_patch_version.sh with no network. Existing cases run with OCCUPIED_VERSIONS unset and must still pass, including plus-one from 0.1.1 to 0.1.2, patch-only arithmetic, and the current heading-disagreement reject. New cases set OCCUPIED_VERSIONS on a fixture copy: next patch occupied and the following patch free, with only the free version's heading written; several consecutive occupied patches with one free version written; an occupied later patch that is not the next patch, so plus-one is still chosen; a set that occupies the first candidate and fifty further patches, with a non-zero exit, byte-identical files, and standard error naming the cap; a malformed token, with a non-zero exit and byte-identical files; a chosen free version whose heading already exists, with a non-zero exit and byte-identical files; and an intermediate occupied version that already has a heading, which must not reject if the chosen free version has no heading. The helper scripts are read to confirm they name no git command, no host, and no URL.

The JSON parser is checked by running tools/test_occupied_pubdev_versions.sh against the fixture JSON directory, including standard-input invocation, a retracted version present in the printed list, a list that includes versions other than latest.version, an empty versions array, a missing versions key, and invalid JSON. The full check suite is run so the new stage appears as passed, and a deliberately failing parser test is shown to stop that stage.

The release workflow is checked by parsing it as YAML and reading the occupancy step: the GET URL and Accept header, the absence of an Authorization header and of a query string, failure on non-200 and on an empty body, invocation of the parser, export of OCCUPIED_VERSIONS, no git tag listing in that step, the occupancy step index before the bump step, and the tag-collision step still between bump and commit and still failing on a matching tag for the bump output. Publish.yml and checks.yml are checked with a path-scoped git diff against the base that must be empty. Restraint is checked by comparing the top-level pubspec version and changelog headings to the base and listing v-prefixed three-component tags.
