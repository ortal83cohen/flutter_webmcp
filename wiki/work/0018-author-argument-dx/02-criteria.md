# Acceptance criteria: Author argument schema, generated metadata, and agent-visible decode errors

## Frozen

- Frozen at: 2026-10-02
- Frozen by: orchestrator

## Criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-001 | When a tool is built through the decoding factory of `WebMcpTool` with a field list and no input schema argument, the registered descriptor's input schema shall be an object schema whose type entry is the string object, whose `additionalProperties` entry is false, and whose properties map has one entry per declared field key. | A test in `test/registry_test.dart` builds such a tool and asserts those three entries on the descriptor's input schema. | The same factory called with a non-empty input schema map leaves that map's own entries in place and adds no object wrapper, properties map or `additionalProperties` entry of its own. |
| AC-002 | When a field list contains at least one required field and at least one non-required field, the derived input schema shall carry a required array naming only the required keys; when every field is non-required, the derived schema shall carry no required entry at all. | The same test asserts the required array's contents for a mixed field list and asserts the key is absent for an all-optional field list. | A derived schema for an all-optional field list that still contains a required key, or a required array that names a non-required field. |
| AC-003 | When a declared field has the string shape, the boolean shape, the safe-integer shape or the finite-double shape, its derived property schema shall be respectively a type of string, a type of boolean, a type of integer carrying a minimum equal to the decoder's inclusive lower bound constant and a maximum equal to its inclusive upper bound constant, and a type of number carrying no additional keyword. | The same test asserts each of the four property schemas against literal expected maps. | A safe-integer property schema with no minimum or no maximum entry, or a finite-double property schema carrying any keyword beyond its type entry. |
| AC-004 | When a declared field has the enumeration shape, its derived property schema shall be a type of string plus an enum array equal to the field's allowed-names list, including when that list is empty. | The same test asserts the property schema for an enumeration field with two allowed names and for one with an empty allowed-names list. | An enumeration property schema with no enum array, or an enum array whose contents differ from the field's allowed-names list. |
| AC-005 | When a declared field is marked nullable, its derived property schema shall be a two-element union under the keyword anyOf, holding the field's non-null schema first and an object whose type entry is the string null second. | The same test asserts the union for a nullable string field and for a nullable enumeration field. | A non-nullable field whose derived property schema is wrapped in a union, or a nullable field whose union omits the null member. |
| AC-006 | When a declared field has the list shape or the map shape and declares a child field, its derived property schema shall be respectively a type of array with an items entry holding the child's derived schema, and a type of object with an `additionalProperties` entry holding the child's derived schema, recursing to any depth the field list declares. | The same test asserts the derived schema for a list of nullable integers and for a map of lists of strings. | A list or map property schema whose child entry is absent while a child field is declared, or a nested child schema that does not match the schema the same child shape produces at the top level. |
| AC-007 | When a declared field has the list shape or the map shape and declares no child field, its derived property schema shall carry only the base array or object type entry and no items entry and no `additionalProperties` entry, and the tool shall still construct without throwing. | The same test builds a tool with a childless list field and asserts the property schema and that construction succeeded. | Construction throwing for a childless list or map field, since that would change existing behaviour. |
| AC-008 | When two tools are built from the same field list with no input schema argument, mutating a nested property map reached through the first tool's descriptor shall leave the second tool's descriptor unchanged. | The same test builds two tools from one field list, mutates a nested map through the first, and asserts the second's nested map is unchanged. | A mutation through one descriptor that is visible through the other. |
| AC-009 | When a tool is built through the plain `WebMcpTool` constructor with no input schema argument, the registered descriptor's input schema shall remain an empty map. | The same test asserts the descriptor's input schema is empty for a handler-only tool. | A derived object schema appearing on a tool built without a field list. |
| AC-010 | When a domain-action annotation sets a title, the generated tool literal shall pass that title to the emitted `WebMcpTool`; when the annotation omits the title, the generated output shall contain no title member. | A builder test in `packages/webmcp_flutter_generator/test/generator_test.dart` asserts the emitted source contains the title argument for a method that sets it. | A method that sets no title whose generated output contains a title member, including one passing a null literal. |
| AC-011 | When a domain-action annotation sets a debugging hint, the generated tool's emitted annotations literal shall carry that boolean; when the annotation omits it, the emitted annotations literal shall carry no debugging member and shall not emit false in its place. | The same builder test asserts the debugging argument is present inside the emitted annotations literal for a method that sets it, and absent for one that does not. | A generated annotations literal that emits a debugging value of false for a method whose annotation omitted the hint. |
| AC-012 | When a domain-action annotation sets an origin list, the generated tool literal shall pass a string list literal with the same elements in the same order to the emitted `WebMcpTool`, including when the author declared that list empty; when the annotation omits the list, the generated output shall contain no origin-list member. | The same builder test asserts the emitted argument for a two-element list, for an empty list, and for an absent list. | A method that sets no origin list whose generated output contains that member, or an emitted list whose element order differs from the annotation's. |
| AC-013 | When a domain-action annotation sets a title that is empty or contains only whitespace, the generator shall report an invalid-generation-source error whose message names the offending method. | The same builder test collects the builder log the way the existing negative generator tests do, and asserts the log contains an invalid-generation-source message that includes the method name. It does not assert that the test function observes a thrown error. | A valid non-empty title that produces that log entry. |
| AC-014 | When an annotated method sets none of the title, the debugging hint and the origin list, the generated source shall contain none of those three member names. | The same builder test asserts the emitted source for an annotation that sets none of the three contains no title member, no debugging member and no origin-list member. | Emitted source for that fixture that contains any of those three members. |
| AC-015 | When the domain-action annotation class is used in a const context without setting any of the three new fields, it shall compile, and the generator package and the annotation package shall each analyze with no info, warning or error. | The analysis stages of `bash tools/check.sh` for the annotation and generator packages pass, and the generator's example fixture compiles. | An analysis finding in either package, or a const construction that no longer compiles. |
| AC-016 | When declared-field decoding rejects an argument key that no field declares, it shall throw an invalid-arguments exception whose key property is that caller-supplied key and whose reason property is the unknown value of the decode-failure reason enum. | A test in `test/registry_test.dart` invokes a field-list tool with one undeclared key and asserts both properties on the caught exception. | A declared key present in the argument map that is reported as unknown. |
| AC-017 | When declared-field decoding finds a required declared key absent from the argument map, it shall throw an invalid-arguments exception whose key property is that declared key and whose reason property is the missing value of the enum. | The same test omits a required key and asserts both properties. | A non-required declared key absent from the argument map, which shall not throw and shall be absent from the decoded map handed to the callback. |
| AC-018 | When declared-field decoding rejects a present value because it is null for a field that is not nullable, is of the wrong Dart type, is an integer outside the inclusive safe range, is a non-finite double, is a string outside the allowed-names list, is a non-list value for a list field, is a non-map value for a map field, or carries a non-string key inside a map value, or is a list or map field declared with no child, it shall throw an invalid-arguments exception whose reason property is the type value of the enum and whose key property is the declared key of the top-level field being decoded. | The same test drives each of those rejections and asserts the reason and the key for every one. | A value that satisfies the same field's shape, which shall decode and reach the callback without throwing. |
| AC-019 | When declared-field decoding rejects a value nested inside a declared list element or map value, the reported key shall be the top-level declared key of that list or map field. | The same test supplies a wrongly typed element inside a declared list of strings and asserts the reported key is the list field's own key. | A reported key equal to the nested child field's declared key rather than the top-level key. |
| AC-020 | When a declared-field decode failure reaches the native publisher, the encoded response shall carry an error object whose code entry is the string invalidArguments, whose retryable entry is false, and whose details entry is a map with exactly two string entries: the failed key and the reason name. | A test in `test/native_publisher_test.dart` invokes a published field-list tool with an invalid argument and asserts the decoded response's error object entry by entry. | An encoded response whose error object has a third details entry, a changed code, or a retryable value of true. |
| AC-021 | When a declared-field decode failure reaches the native publisher, the encoded response shall not contain the rejected value, the argument map, an exception message or a stack. | The same publisher test passes a distinctive string as the rejected value and asserts the encoded response does not contain that string, the runtime type name of the exception, or the word Exception. | The distinctive rejected value, a message or a stack frame appearing anywhere in the encoded response. |
| AC-022 | When the invalid-arguments exception is constructed through its existing no-argument constructor, its details property shall be null and both the key and reason properties shall be null, and that constructor shall remain usable in a const context. | A test in `test/registry_test.dart` constructs the exception with no arguments in a const context and asserts all three properties are null. | The no-argument constructor producing a non-null details map, or no longer compiling in a const context. |
| AC-023 | When a generated tool's decoder rejects an argument, the generated invoker shall return a map whose ok entry is false and whose error object has a code entry of invalidArguments and a retryable entry of false, shall not throw out of the invoker, and shall include no details entry. | A test in `packages/webmcp_flutter_generator/example/test/live_instance_test.dart` invokes a generated tool with an invalid argument and asserts the returned map's entries and that no exception propagated. | The generated invoker throwing instead of returning, or the returned error object gaining a details entry. |
| AC-024 | When a generated tool's decoder rejects an argument, the domain method shall not run. | The same fixture test asserts the service's recorded call count is zero after the rejected invocation. | A recorded call on the service after a rejected invocation. |
| AC-025 | When a `WebMcpAction` is constructed with a field list and a call callback, the registered tool shall decode the arguments before the callback runs, the callback shall receive only the declared keys, and a rejected argument map shall leave the callback uninvoked. | A test in `test/widget_layer_test.dart` pumps such an action inside a screen scope, invokes through the registry with a valid map and asserts the callback received the decoded map, then invokes with an undeclared key and asserts the callback count did not increase. | A callback invoked with a raw argument map containing an undeclared key. |
| AC-026 | When a `WebMcpAction` is constructed with a non-null field list and the one-argument callback rather than the call callback, the constructor shall throw an argument error, and the existing exactly-one-callback error shall still be reported first when neither or both callbacks are supplied. | The same widget test asserts an argument error for the rejected pairing and asserts the existing error still fires for the zero-callback and two-callback cases. | A field list paired with the call callback, or either callback supplied alone without a field list, that fails to construct. |
| AC-027 | When a mounted `WebMcpAction` with a field list is rebuilt with a different field list, the registered tool shall keep decoding against the field list captured at the first mount. | The same widget test rebuilds the action with a field list declaring a different key, then invokes with the originally declared key and asserts the call succeeds, and invokes with the newly declared key and asserts it is rejected. | An invocation using a key declared only by the rebuilt field list that is accepted. |
| AC-028 | When a mounted `WebMcpAction` with a field list is rebuilt with a new call callback, a successful decode shall dispatch to the newest callback. | The same widget test rebuilds with a second callback and asserts the second one received the invocation and the first did not. | The first-mount callback receiving an invocation after a rebuild supplied a new one. |
| AC-029 | When a `WebMcpAction` supplies a field list and no input schema, the registered descriptor's input schema shall be the object schema derived from that field list. | The same widget test asserts the registered descriptor's input schema has an object type entry and a properties entry for each declared key. | A registered descriptor carrying an empty input schema for an action that declared a field list. |
| AC-030 | When a `WebMcpAction` supplies a field list, the widget shall render its child unchanged, the tool shall remain invokable while the child is disabled or visually hidden, and unmounting the action shall remove the registered name only when that state owns it. | The same widget test asserts the rendered subtree is the supplied child, invokes the tool while the child is disabled and asserts the callback ran, and asserts the registry no longer lists the name after unmount. | A wrapper widget appearing around the child, a disabled child causing the invocation to fail, or a registered name surviving the unmount of its owning action. |

## Non-functional criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-031 | When any tool is invoked, no code path shall validate the argument map against an input schema; schema derivation shall run only while a descriptor is being constructed. | A test in `test/registry_test.dart` invokes a plain tool whose hand-written schema declares a required key that the argument map omits and asserts the handler still ran, and a field-list tool whose derived schema is present and asserts the invocation outcome is decided by decoding alone. | An invocation that fails because the argument map violated a schema rather than the declared field list. |
| AC-032 | When the package's public library is imported, the decode-failure reason enum and the schema-derivation function shall both be reachable, and the existing exported names shall remain reachable. | The enumerated export list in `test/webmcp_public_surface_test.dart` names both new identifiers and the suite passes. | A new identifier reachable only through a source-directory import, or an existing exported name removed. |
| AC-033 | When the full check script is run, every stage that script defines shall report passed. | `bash tools/check.sh` is run and its complete stage output is pasted into the verification notes. | Any stage reporting a failure, or a claimed pass with no pasted command output. |
| AC-034 | When a decode failure's details map is serialized by the native publisher, it shall remain a string-keyed map of string values with no nested structure, so it stays inside the publisher's existing depth, shape and size limits. | The publisher test asserts the decoded details entry is a map whose every value is a string and whose entry count is two. | A details entry holding a nested map, a list, a number or a boolean. |

## Explicitly not required

- A field key or a failure reason on the generated-tool decode path. AC-023 deliberately locks the current behaviour of that path, which returns an envelope with no details entry.
- A change to the operation outcome or the log kind produced by a generated decode failure. It remains a completed operation logged as invoked.
- Any runtime validation of arguments against an input schema, for manual or generated tools.
- Deep immutability of the derived schema's nested maps. The existing shallow-copy semantics are unchanged.
- Rejecting a list or map field declared with no child at construction time. AC-007 requires construction to still succeed.
- Reconciling a `WebMcpAction` registration when a rebuild supplies a different descriptor value, including a different field list. AC-027 requires the opposite.
- An output schema on any tool, generated or manual.
- Generated route wrapping, in-flight invocation cancellation, and multiple Flutter view operation.
- Updates to `wiki/product/webmcp-contract.md` and `README.md`, including documenting the field key and the three reason values. Those belong to the document phase.
