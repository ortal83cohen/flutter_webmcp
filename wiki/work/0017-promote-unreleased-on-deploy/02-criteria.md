# Acceptance criteria: Promote Unreleased changelog notes into the deployed version

## Frozen

- Frozen at: 2026-09-25
- Frozen by: main agent

## Criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-001 | When `tools/bump_patch_version.sh` runs against a fixture whose CHANGELOG.md contains no line equal to `## Unreleased`, it shall exit zero, write the bullet `- Automated patch release from main.` under the new dated heading, and shall not insert a line equal to `## Unreleased`. | Run the helper against a temporary copy of a no-Unreleased fixture with `RELEASE_DATE` set; assert exit zero, that the new section body line equals that bullet, and that `grep` for the exact heading line returns no match. | Add one exact `## Unreleased` line and one hyphen-space bullet under it, then re-run: the new section body shall equal that hyphen-space bullet and shall not equal the automated sentence. |
| AC-002 | When the changelog contains exactly one line equal to `## Unreleased` and the span until the next heading that begins with exactly two hashes and a space contains no line that begins with hyphen then space, the helper shall write the automated bullet under the new dated heading and shall leave the exact `## Unreleased` line in the file. | Run a heading-only fixture; assert the new section body is `- Automated patch release from main.` and that the file still contains exactly one line equal to `## Unreleased`. | Insert one hyphen-space line into that span and re-run: the new section body shall be that hyphen-space line, not the automated bullet. |
| AC-003 | When the Unreleased span contains a heading that begins with three hashes and contains no line that begins with hyphen then space, the helper shall write the automated bullet, shall leave the `## Unreleased` line, and shall leave that three-hash heading in the span. | Run a subsection-only fixture; assert the automated bullet is present, the exact Unreleased heading remains, and the three-hash heading remains. | Add a hyphen-space line under the three-hash heading and re-run: that hyphen-space line shall appear under the new dated heading and the automated bullet shall be absent from the new section. |
| AC-004 | When the Unreleased span contains one or more lines that begin with hyphen then space, and one or more of those lines is followed immediately by a non-blank whitespace-prefixed wrap line, the new dated section body shall be those start lines and wrap lines in document order, each byte-identical to the pre-run line, and shall not contain `- Automated patch release from main.` | Run a wrapped mid-file fixture; compare each new-section body line to the corresponding pre-run Unreleased start or wrap line. | Run a populated fixture whose Unreleased items are single-line hyphen-space lines with no wrap line: the new body shall be those start lines only, with no whitespace-prefixed line invented. |
| AC-005 | When a populated Unreleased promotion exits zero, the written changelog shall contain exactly one line equal to `## Unreleased`, and the span under that heading until the next exactly-two-hash heading shall contain no line that begins with hyphen then space and no wrap line that was copied into the new section. | After the wrapped-fixture run, assert heading count one and that `grep` of that span finds no copied start or wrap line. | Run the helper a second time on the written tree: the second new section body shall be `- Automated patch release from main.`, proving the first run emptied the list items. |
| AC-006 | When the changelog contains two or more lines each equal to `## Unreleased`, the helper shall exit non-zero, print an English message on standard error that contains the word Unreleased, print no version on standard output, and leave pubspec.yaml and CHANGELOG.md byte-identical to the pre-run copies. | Run a two-heading fixture; compare exit status, empty stdout, stderr text, and checksums of both files. | Run a fixture with exactly one exact heading and one hyphen-space bullet: the helper shall exit zero and both files shall differ from their pre-run copies. |
| AC-007 | When the helper exits zero, every numbered version section already in the file, meaning each heading that names a three-component version and a date plus the lines until the next exactly-two-hash heading, shall be byte-identical to the corresponding pre-run section. | For a mid-file fixture that has numbered sections above and below Unreleased, extract those sections before and after and compare them. | Change one numbered-section bullet in a scratch copy after the run: the comparison shall report a difference. |
| AC-008 | When the helper exits zero, standard output shall be exactly one line equal to the new version string with no other text. | Capture stdout from a missing-Unreleased run and from a populated-Unreleased run; compare each to the chosen version only. | Capture stdout from the two-heading reject: it shall be empty, so a version line cannot appear on failure. |
| AC-009 | When the helper exits non-zero, neither pubspec.yaml nor CHANGELOG.md in the target root shall differ by one byte from its pre-run content. | Checksum both files before and after the two-heading reject and after an existing heading-disagreement reject; compare. | Re-run the comparison against a copy modified by one byte after checksumming: the comparison shall report a difference. |
| AC-010 | When the existing `valid-patch` and `valid-leading-blank` fixtures run, each shall still contain the bullet `- Automated patch release from main.` on the same line the current test script asserts, and `tools/test_bump_patch_version.sh` shall report PASS for both. | Run those two cases and assert PASS plus the current line-number bullet checks. | Run the wrapped populated fixture through those same line-number checks: they shall fail, proving those checks still look for the automated sentence rather than any body line. |
| AC-011 | When the change is complete, `wiki/work/0009-pubdev-publish-workflow/02-criteria.md` shall be byte-identical to that file on the work-item base commit. | Path-scoped git diff against the base; assert empty output. | Append a blank line to a scratch copy and diff against the copy: the diff shall be non-empty. |
| AC-012 | When the changelog has no line equal to `## Unreleased` but has a lookalike heading, either `## Unreleased - 2026-01-02` or `## [Unreleased]` or `## unreleased`, and has hyphen-space lines under that lookalike, the helper shall write the automated bullet and shall leave those lookalike lines and the hyphen-space lines under them in place. | Run one fixture per lookalike; assert the automated bullet is present and the lookalike heading and its list items remain. | Replace the lookalike with the exact `## Unreleased` line and re-run: those hyphen-space lines shall appear under the new dated heading and shall be absent from the Unreleased span. |
| AC-013 | When `## Unreleased` sits below one or more numbered version headings and above another numbered version heading, the helper shall take start and wrap lines from that mid-file span, insert the new dated section immediately after the Changelog title, and leave the numbered sections byte-identical. | Run the mid-file wrapped fixture; assert the new heading is the first two-hash heading after the title, the promoted lines came from the mid-file span, and numbered sections match their pre-run bytes. | Remove the mid-file Unreleased heading and leave its bullets under a numbered section, then re-run: those bullets shall remain in that numbered section and the new body shall be the automated sentence. |
| AC-014 | When `OCCUPIED_VERSIONS` contains the plus-one version and not the following patch, and Unreleased is populated, the helper shall write the promoted start and wrap lines under the free version heading and shall not insert a new heading for the occupied plus-one version. | Fixture pubspec `0.1.1`, occupied `0.1.2`, populated Unreleased: assert stdout `0.1.3`, promoted body under `0.1.3`, no new `0.1.2` heading, Unreleased emptied. | Unset `OCCUPIED_VERSIONS` on the same files: the promoted body shall sit under `0.1.2`, not `0.1.3`. |
| AC-015 | When `.github/workflows/release.yml` is compared to the work-item base, it shall be byte-identical, and it shall still contain the job-level loop guard on the prefix `chore(release): v`. | Path-scoped git diff of that file; grep the file for that prefix on the job condition and the commit step. | Append a blank line to a scratch copy and diff against the copy: the diff shall be non-empty. A scratch copy that changes the commit prefix shall fail the prefix grep. |
| AC-016 | When the change is complete, the repository `CHANGELOG.md` numbered sections and the live `## Unreleased` heading with its current list items shall be byte-identical to the work-item base, the top-level pubspec version line shall equal the base, and the repository shall gain no new tag named `v` followed by three numeric components. | Diff `CHANGELOG.md` and `pubspec.yaml` against the base; list tags of that shape and compare to the base tag list. | In a scratch clone, delete a live Unreleased bullet, bump the pubspec patch, and create such a tag: each check shall report a difference. |
| AC-017 | When `tools/test_bump_patch_version.sh` runs, every case that existed before this work item shall still pass, including `valid-patch`, `valid-leading-blank`, `valid-minor-untouched`, occupied-skip successes, and the current reject cases. | Run the test script and assert those named cases print PASS. | Change one existing fixture expectation so it disagrees with the helper: the script shall exit non-zero and name that case. |

## Non-functional criteria

| ID | Criterion | How it is checked | Negative case |
|---|---|---|---|
| AC-018 | When `tools/bump_patch_version.sh` is read and when `tools/test_bump_patch_version.sh` runs, neither shall open a network connection or invoke git. | Read both scripts and confirm they reference no host name, no URL, and no git command; run the test script with no network reachable and assert exit status zero. | Add a temporary case that resolves a host name or calls git and run the suite offline: that case shall fail. |
| AC-019 | When a line under Unreleased begins with whitespace but is not immediately after a hyphen-space start line or a wrap line of that item, that line shall not appear in the new dated section and shall not by itself cause promotion. | Run a fixture whose Unreleased span has only an orphan whitespace-prefixed line, or a whitespace-prefixed line after a blank line and no hyphen-space line: assert the automated bullet is written and the orphan line remains under `## Unreleased`. | Place the same whitespace-prefixed line immediately after a hyphen-space line and re-run: that line shall appear in the new section as a wrap line and shall be absent from the Unreleased span. |

## Explicitly not required

- Implementing work item 0013, adding `tools/request_changelog.py`, adding a `.changes/` tree, or marking 0013 superseded.
- Editing `wiki/work/0009-pubdev-publish-workflow/02-criteria.md`.
- Editing `.github/workflows/release.yml`, `publish.yml`, or `checks.yml`.
- Rewriting already published numbered sections in the live `CHANGELOG.md`, emptying the live Unreleased block, bumping the real package version, or creating a release tag during this work item.
- Accepting dated, bracketed, or case-folded Unreleased headings.
- Flattening wrap lines onto one line.
- Minor bumps, major bumps, or reading commit messages.
- An end-to-end main-branch release during verify. Verification is offline helper tests plus static diffs of the restrained paths.
