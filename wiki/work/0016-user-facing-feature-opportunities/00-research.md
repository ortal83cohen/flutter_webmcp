# Research: Additional features that would benefit a Flutter application author

## Question

Which additional features would benefit a Flutter application author using webmcp_flutter, given what the library already does, what the browser contract withholds, and what external demand exists?

## Answer

The three branches point different ways, and this artifact does not collapse them into one recommendation. current-user-jobs.md finds that the author can already complete the shipped jobs, that the remaining work is author-owned glue the contract already assigns (handler authorization, manual argument checks, page and navigator wiring, and the later ranked duties), and that a library feature which absorbs that glue is rejected as a description of what the author can do now. browser-contract-gaps.md finds that the publisher drops browser-contract capabilities and chooses exposing the execution AbortSignal to the author as the gap that changes what the author can safely ship, while recording library-initiated termination as a constraint, whereas demand-signals.md finds no retrieved author request strong enough to justify a feature or a documentation fix and chooses deferral.

## Findings

### The execution AbortSignal is a disagreement, not a single gap

- Claim: Interpretation A, from browser-contract-gaps.md: the community-group draft and the Chrome imperative page last updated 2026-09-21 define an execution `AbortSignal`. The draft invokes `execute` with the input object and a `ToolExecuteCallbackOptions` whose required `signal` is a new `AbortController` signal. Cancelling a pending execution aborts that signal and fires `toolcancel`. Aborting the registration signal unregisters the tool and does not abort the execution controller. Chrome documents the same callback shape and tells the page to pass `{ signal }` into long-running work such as `fetch`. As of Chrome 153, unregistering with the registration signal does not cancel in-flight executions. The publisher's browser callback accepts only the input value, then calls the Dart handler with `cancelledBeforeDispatch: false`, and never reads a second callback argument. That branch's chosen response is to forward `ToolExecuteCallbackOptions.signal` into the application handler and leave the handler running until the author returns. The library still does not terminate the callback.
- Evidence: Draft IDL and imperative execute steps; Chrome's documented `execute: async ({ url, priority }, { signal })` example, Chrome 153 unregister behavior, and Chrome 156 `debugging` note; the JS `execute` function `(JSAny? input)` and `_executeSafely` passing `cancelledBeforeDispatch: false`.
- Source: browser-contract-gaps.md. - Claim: Interpretation B, stated by browser-contract-gaps.md and also stated by current-user-jobs.md and demand-signals.md: the product contract, verified 2026-09-15, says Chrome 152 page conformance does not supply an invocation signal after callback start, so admitted work may continue and the library does not terminate or replay it. ### Other browser capabilities the publisher does not give the author

- Claim: The WebML Community Group draft status is `CG-DRAFT`, at `https://webmachinelearning.github.io/webmcp`. `Document` has a `modelContext` attribute. `ModelContext` extends `EventTarget` and defines `registerTool`, `getTools`, `executeTool`, `ontoolchange`, `ontoolactivated`, and `ontoolcancel`. The draft source contains no `navigator` attribute for this API. Chrome's imperative documentation registers, lists, executes, and listens on `document.modelContext`, not `navigator.modelContext`. The native publisher reads `document.modelContext` and calls `registerTool` with `name`, `description`, `inputSchema`, `execute`, annotations `readOnlyHint`, `untrustedContentHint`, and `consequentialHint`, plus `{ signal }` from an `AbortController`.

## Constraints discovered

- Tool names are one process-wide namespace of 1 to 128 ASCII letters, digits, underscores, hyphens, or periods. The first live registration owns a duplicate. A later scope skips it and cannot remove the first owner's tool. Source: current-user-jobs.md, citing `wiki/product/webmcp-contract.md:23-29`, `lib/src/webmcp.dart:58-94`, `lib/src/webmcp_scope.dart:28-34`.
- Automatic pages require exactly one Flutter view, settled Navigator evidence, and an opted-in semantic boundary. Navigation evidence does not replace that boundary. Source: current-user-jobs.md, citing `wiki/product/webmcp-contract.md:70-76`, `README.md:259-264`.
- The quoted omissions are constraints, not backlog: "Multiple-Flutter-view operation, positive observation waits, generated route wrapping, generalized service proxies, framework-specific state adapters, custom data providers, Chrome web platform-back-gesture support, in-flight callback termination, deep schema immutability, transactional source registration, notification rollback, automatic cleanup of custom transports, and non-web product support are not delivered." browser-contract-gaps.md cites the same omission list for in-flight callback termination, positive observation waits, and non-web product support, and calls those three constraints. Source: current-user-jobs.md, citing `wiki/product/webmcp-contract.md:146-153`; browser-contract-gaps.md, citing `wiki/product/webmcp-contract.md` lines 146–153.
- Consumers must keep names unique, retain authorization, install every required Navigator adapter, and own session, publisher, scope, generated adapter, and custom transport cleanup. Source: current-user-jobs.md, citing `wiki/product/webmcp-contract.md:155-157`.
- Local handler results and exceptions pass through unchanged. Browser publication separately bounds JSON and sanitizes errors. A dispatch receipt does not prove backend success. Source: current-user-jobs.md, citing `README.md:326-327`, `README.md:572-574`, `wiki/product/webmcp-contract.md:81-83`.
- The publisher bounds JSON depth, encoded size, registration count, and outstanding executions, and it returns an allowlisted failure object rather than a thrown exception. Those limits are library behavior, not draft IDL. Source: browser-contract-gaps.md, citing `lib/src/transport/webmcp_native_publisher.dart` lines 10–25 and 309–365.
- Browser publication is experimental. `WebMcpNativeSupport` has no native-agent-supported value. WebMCP is an experimental browser surface and may change. Property detection is not proof that the native API works. Source: current-user-jobs.md, citing `lib/src/transport/webmcp_native_capabilities.dart:60-75`, `README.md:596-599`; browser-contract-gaps.md, citing `wiki/product/webmcp-contract.md` lines 117–119.
- ADR 0003 is superseded by ADR 0004. Its detection-only publishing decision is not the current contract. Source: current-user-jobs.md, citing `wiki/adr/0003-webmcp-detection-first-registry.md:1-6`, `wiki/adr/0004-use-semantic-page-boundaries-and-app-observation.md:40-55`.
- The draft gates the API on a secure context and on the `tools` permissions policy, default `self`. Cross-origin iframes need `allow="tools"` from the embedding page, and cross-origin visibility also needs `exposedTo` plus `fromOrigins`. Source: browser-contract-gaps.md, citing https://github.com/webmachinelearning/webmcp/blob/main/index.bs lines 597–598 and 1393–1397; https://developer.chrome.com/docs/ai/webmcp/imperative-api, last updated 2026-09-21.
- `document.domain` / `Origin-Agent-Cluster: ?0` disables the API in Chrome's documentation. Source: browser-contract-gaps.md, citing https://developer.chrome.com/docs/ai/webmcp, last updated 2026-08-07.
- Chrome's origin-trial post says the trial starts in Chrome 149 and that the API shape can still change. Source: browser-contract-gaps.md, citing https://developer.chrome.com/blog/ai-webmcp-origin-trial, published 2026-06-09, consulted 2026-09-25.
- The declarative section of the community-group draft is still a TODO, while Chrome's declarative page is a separate, earlier document (last updated 2026-05-18). Source: browser-contract-gaps.md, citing https://github.com/webmachinelearning/webmcp/blob/main/index.bs lines 1282–1284; https://developer.chrome.com/docs/ai/webmcp/declarative-api.
